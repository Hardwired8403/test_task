# Утилита анализа бинарных данных StatData

Небольшой проект на C для сериализации, объединения и сортировки массивов
`StatData`. Утилита читает два бинарных файла, объединяет записи с совпадающими
идентификаторами, сортирует результат и сохраняет его в файл.

## Требования

- Linux x86_64;
- GCC или Clang с поддержкой C11;
- GNU Make.

Внешние библиотеки не требуются.

## Сборка

```sh
make
```

После сборки появятся исполняемые файлы `dump_tool` и `test_dump`.

## Запуск

```sh
./dump_tool <входной-файл-а> <входной-файл-б> <файл-результата>
```

Пример:

```sh
./dump_tool first.bin second.bin result.bin
```

Утилита объединяет записи с одинаковым `id`, сортирует результат по возрастанию
`cost`, выводит первые десять записей в таблице и сохраняет полный результат в
указанный файл. Идентификатор выводится в шестнадцатеричном виде, `count` —
в десятичном, `cost` — в экспоненциальном формате с тремя знаками после
запятой, `primary` — как `n` или `y`, `mode` — в двоичном виде.

## Тестирование

Собрать программу и запустить интеграционные тесты:

```sh
make test
```

Тестовый запускатель создаёт входные файлы, запускает `dump_tool`, проверяет
содержимое результата и консольный вывод. Также проверяются пустые файлы,
повторяющиеся идентификаторы, отрицательные значения, усечённые файлы и
переполнение `count`.

Удалить результаты сборки:

```sh
make clean
```

## Формат бинарного файла

`StoreDump` и `LoadDump` используют версионированный формат с порядком байтов
little-endian:

1. 8 байт сигнатуры `STDATA01`;
2. версия формата (32 бита);
3. количество записей (64 бита);
4. записи фиксированного размера: знаковый `id` (64 бита), знаковый `count`
   (32 бита), `cost` в формате IEEE-754 binary32 и байт флагов.

Младший бит байта флагов хранит `primary`, следующие три бита — `mode`.
Неподдерживаемая версия, лишние байты, усечённые данные и нечисловая или
бесконечная стоимость считаются ошибками.

Каждый входной файл может содержать не более 100 000 записей, результат —
не более 200 000 записей.

## Алгоритмы

- `JoinDump` использует хеш-таблицу с открытой адресацией: ожидаемое время
  выполнения O(n), дополнительная память O(n), где n — суммарное число записей
  во входных массивах.
- `SortDump` использует `qsort`: время сортировки u уникальных записей —
  O(u log u).

Объединение через предварительную сортировку и последовательный проход
потребовало бы O(n log n). Хеш-таблица позволяет избежать этой дополнительной
сортировки.

## Структура проекта

```text
.
├── dump_tool.c   # исполняемая утилита обработки файлов
├── statdata.c    # сериализация, объединение и сортировка
├── statdata.h    # тип StatData и интерфейс библиотеки
├── test_dump.c   # интеграционные тесты
└── Makefile      # сборка, тестирование и очистка
```
